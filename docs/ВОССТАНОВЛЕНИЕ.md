# iSwim CRM: как восстановить систему, если всё сломалось

Документ для вас или любого программиста. Мой (Claude) доступ не нужен.

## Из чего состоит система

| Часть | Где живёт | Чем защищена |
|---|---|---|
| Сайт (то, что видят тренеры) | GitHub, репозиторий `vinogradov46/iSwim-CRM`, публикуется на crm.iswim.by | История в GitHub |
| База данных (дети, оплаты, посещения), функции, правила доступа | Supabase, проект `rpvzjqlhihphspaxocqx` | Ночная копия на Google Диске |
| Рассылка в Telegram, ночная копия | Supabase Edge Functions | Исходники в репозитории, папка `supabase/functions` |
| Токен Telegram-бота | Секрет `TELEGRAM_BOT_TOKEN` в Supabase | Хранится только у вас; при потере — заново у @BotFather |

## Где копии

Google Диск → папка «iSwim CRM — резервные копии» → `iswim-backup-ГГГГ-ММ-ДД.json.gz`. Каждую ночь около 01:30 по Минску, хранятся 60 дней.
В каждой копии: все данные, список миграций (вся структура базы), логины сотрудников, расписание ночных задач.
Копии содержат персональные данные детей и родителей и хэши паролей сотрудников. Не открывайте папку посторонним.

## Если удалили или испортили часть данных

Скажите программисту, какие таблицы и за какой день. Достаточно взять копию до поломки, распаковать (`gunzip`), найти нужные строки в JSON и вернуть их SQL-запросом.

## Если проект Supabase потерян целиком

1. Создайте новый проект на supabase.com (любой регион Европы). Запомните его ref (часть адреса `https://ref.supabase.co`).
2. Скачайте нужную копию с Диска. Клонируйте репозиторий `vinogradov46/iSwim-CRM`, установите Supabase CLI.
3. В папке репозитория: `supabase link --project-ref НОВЫЙ_REF`, затем `supabase functions deploy restore --no-verify-jwt`.
4. В Supabase → Edge Functions → Secrets создайте секрет `RESTORE_KEY` с любым длинным случайным значением.
5. Отправьте файл копии в функцию (одной командой):
   ```
   curl -X POST "https://НОВЫЙ_REF.supabase.co/functions/v1/restore" -H "x-key: ЗНАЧЕНИЕ_RESTORE_KEY" --data-binary @iswim-backup-ДАТА.json.gz
   ```
   Функция сама применит структуру базы (миграции), перенесёт логины сотрудников, зальёт данные всех таблиц и вернёт расписание ночных задач. В ответе будет отчёт: сколько строк в каждой таблице и список ошибок (`migration_errors` должен быть пустым).
6. После восстановления удалите функцию `restore` и секрет `RESTORE_KEY`.
7. Задеплойте остальные функции: `supabase functions deploy tg --no-verify-jwt` и `supabase functions deploy backup --no-verify-jwt`. Добавьте секрет `TELEGRAM_BOT_TOKEN`, затем один раз вызовите настройку вебхука (`/functions/v1/tg?job=setup` с заголовком `x-key` = значение `cron_key` из таблицы `private.app_keys` нового проекта).
8. В репозитории (файл `src/lib.ts`) замените адрес и публичный ключ Supabase на новые. Сайт пересоберётся сам после коммита.
9. Проверьте вход директора и одного тренера, откройте занятие и расписание.

## Если потерян репозиторий GitHub

Сайт можно собрать из любой локальной копии репозитория: `npm ci && npm run build`, содержимое папки `dist` выложить на любой хостинг. Копию репозитория стоит хранить и на своём компьютере: `git clone https://github.com/vinogradov46/iSwim-CRM`.

## Что копия НЕ содержит

- токен Telegram-бота и ключи Supabase (их нужно создать заново);
- сам репозиторий сайта (он на GitHub);
- историю входов сотрудников.

## Пробное восстановление (18.11.2026)

Ночная копия была восстановлена в пустой тестовый проект Supabase. Сверка с боевой базой: 20 таблиц, 6749 строк, 13 логинов сотрудников, 110 функций, 46 правил доступа и 4 ночные задачи совпали. Контрольные суммы данных 11 основных таблиц (дети, семьи, группы, занятия, записи, посещения, оплаты, сотрудники и др.) идентичны боевым.

Что нужно сделать руками после восстановления (функция напишет это в `notes`):
- задать заново ключи приложения `backup_key` и `backup_url` в таблице `private.app_keys` (значения секретов в копию намеренно не попадают);
- добавить секрет `TELEGRAM_BOT_TOKEN` и вызвать настройку вебхука (шаг 7).
